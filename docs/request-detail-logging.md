# 请求详情日志

请求详情日志用于在 API 调用最终失败时排查请求参数和渠道路由。它与普通消费日志分表存储，
不会扩大普通日志列表查询的数据量，也不参与计费。

## 管理设置

后台“日志维护”提供以下配置：

- `request_detail_setting.mode`
  - `all`：记录所有已完成的 API 请求。
  - `failed`：只记录完整重试流程结束后仍失败的逻辑请求，默认值。
  - `none`：不读取或写入请求详情。
- `request_detail_setting.retention_days`：最长保留天数，默认 `7`。
- `request_detail_setting.max_storage_mb`：详情日志最大逻辑容量，默认 `5120` MB。

时间和容量限制同时生效。容量达到 90% 时，后台优先删除最旧的成功详情，随后在需要时
删除最旧的失败详情，直到容量低于 80%。SQLite 所在磁盘剩余空间不足 5% 或 2 GB 时，
写入会暂停。清理或写入失败只会丢弃详情，不能阻塞用户 API 请求。

## 采集与安全边界

每个逻辑请求最多产生一条详情。某个渠道失败但后备渠道成功时，最终结果为成功；在
`failed` 模式下不会保存该请求。记录内容包括：

- 请求 ID、用户、令牌、模型、最终分组、HTTP 状态和最终错误；
- 实际尝试过的分组、渠道、优先级和最终渠道；
- JSON、URL 编码表单或 multipart 表单中的文本字段；
- multipart 文件的字段名、文件名、类型和大小，不保存文件字节。
- 返回给调用方的 JSON、文本和 SSE 响应正文，以及响应状态、类型和实际字节数。

请求体最大保存 64 KB，超过后只记录大小和省略原因。`Authorization`、Cookie、API Key、
访问令牌、密码和 Secret 等字段会递归脱敏。响应正文最大保存 1 MiB，超过后保存前 1 MiB
并标记截断；图片、音频、视频和文件等二进制响应只记录类型与大小，不保存文件字节。旧版本
生成的历史记录不会补录响应正文。

采集层位于令牌鉴权之后、渠道分发之前，因此不会保存未通过鉴权的外部请求，但能覆盖
无可用渠道、模型限制、分组权限、速率限制和控制器内上游失败。控制器只写入最终错误
上下文，统一采集中间件在完整调用链返回后生成一条记录，避免重试或嵌套处理造成重复详情。

## 性能设计

请求处理线程只检查当前模式，并复制不超过 64 KB 的已有请求体缓存及不超过 1 MiB 的文本
响应。默认的仅失败模式只缓存 HTTP 错误响应，成功响应不分配正文缓冲；全部记录模式才会缓存
成功响应。响应捕获旁路包装 `ResponseWriter`，不会改变状态码、响应头、正文或流式刷新行为。
JSON 解析、脱敏、gzip 压缩和数据库写入全部由后台线程执行：

- 失败详情与成功详情使用独立有界队列，失败队列优先；
- 每 100 条或 250 ms 批量写入一次；
- 队列饱和时先丢弃成功详情，并记录成功/失败丢弃计数；
- 每分钟检查容量，每小时执行过期清理；
- 写入器在内存中增量维护容量，每 5 分钟与数据库校准一次，仅在实际清理后立即重算，避免频繁全表聚合；
- 进程退出时最多等待 3 秒刷新队列。

详情表记录压缩后的 `storage_bytes`，容量统计无需在请求路径扫描数据库。物理数据库文件可能
包含页、索引和 WAL 开销；删除后的 SQLite 文件也可能保持高水位，但空闲页会被后续写入复用。

## 管理接口

以下接口仅管理员可访问：

- `GET /api/request-detail/`：分页查询元数据，支持 `request_id`、`username`、`model_name`、
  `outcome` 和时间范围过滤；不会返回压缩载荷。
- `GET /api/request-detail/:request_id`：按需解压并返回单条脱敏详情。
- `GET /api/request-detail/stats`：返回记录数、逻辑容量、队列长度、写入及丢弃计数。

Default 前端在使用日志详情和独立“请求详情”页面按需加载内容；Classic 前端在使用日志页的
“请求详情”页签提供相同查询和查看能力。
